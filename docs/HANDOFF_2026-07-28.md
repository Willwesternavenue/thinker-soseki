0. **破壊的テストは既定で skip される。skip は安全装置であって免除ではない**
   （2026-07-30 追加）。`clean_corpus` を使う**13ファイル**は、接続先が本物の
   コーパスに見えると skip する。何もしなければこの13ファイルは**恒久的に
   走らない回帰の穴**になるので、走らせる時機を運用として決めてある。

   | いつ | 何を |
   |---|---|
   | **main へマージする前（通過条件）** | 破壊系を含めて全件通す。ここを飛ばさない |
   | コーパス層（`aozora/` `creative/`）を触ったとき | その領域だけでも通す |
   | プロンプト・文言だけの変更 | 既定の skip のままでよい |

   走らせ方は2つ。**第一分岐を常用経路にすること**:
   ```bash
   # ① 専用スタック（本筋。開発DBに触れないので退避も要らない）
   SUPABASE_TEST_URL=... SUPABASE_TEST_SECRET=... uv run pytest
   # ② 逃げ道（最後の網。直前に退避を取ったと分かっている場合のみ）
   SOSEKI_ALLOW_DESTRUCTIVE_TESTS=1 uv run pytest
   ```
   ②の行数ヒューリスティック（`source_chunks` が500行超なら止める）は最後の網で
   あって常用するものではない。**次の区切りで `SUPABASE_TEST_URL` 用のスタックを
   立て、①を既定にすること**（未着手）。

1. **worker の `uv run pytest` はローカルDBを全消しする**（`clean_corpus` fixture）。
   上の安全装置を迂回した場合はこれが起きる。実行前に必ず退避すること。
   退避・復元（ホストの pg_dump はバージョン不一致で使えない。docker 経由で）:
   ```bash
   # 退避
   docker exec supabase_db_thinker-soseki pg_dump -U postgres -d postgres \
     --data-only --no-owner \
     -t canonical_works -t work_editions -t aozora_manifest_entries \
     -t canonical_work_review_queue -t sources -t source_chunks \
     -t thought_cards -t thought_evidence_links -t thought_questions \
     -t judgment_rules -t judgment_rule_versions -t judgment_rule_evidence \
     -t creative_profiles -t creative_cards \
     -t creative_generations -t creative_traces \
     > backups/phase_c_data_$(date +%F).sql
   # 復元
   docker exec -i supabase_db_thinker-soseki psql -U postgres -d postgres -q \
     -v ON_ERROR_STOP=1 --single-transaction \
     -c "set session_replication_role = replica;" -f - < backups/<最新の退避>.sql
   ```
   復元後は必ず行数を突き合わせる（`source_chunks` 10,152 / `thought_cards` 57 /
   `judgment_rules` 29 が 2026-07-30 時点の値）。
   ⚠️ **退避対象は `clean_corpus` が消すテーブルと必ず一致させること**。
   2026-07-30 まで `creative_generations` / `creative_traces` が退避から漏れており
   （fixture は消す）、テストを流すと生成履歴だけ復元できなかった。
   テーブルを増やしたら conftest と両方を直す。
   最新の退避が `backups/phase_c_data_2026-07-30.sql`（199MB・gitignore 済み）にある。
   これを失った場合の完全再構築は §12.1 の CLI 手順 + Phase C の ingest +
   `retag`（LLM 数ドル・数時間）。
