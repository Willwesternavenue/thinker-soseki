## 2. ⚠️ 最重要の運用注意（このセッションで実際に踏んだ罠）

1. **worker の `uv run pytest` はローカルDBを全消しする**（`clean_corpus` fixture）。
   実行前に必ず退避すること。退避・復元（ホストの pg_dump はバージョン不一致で
   使えない。docker 経由で）:
   ```bash
   # 退避
   docker exec supabase_db_thinker-soseki pg_dump -U postgres -d postgres \
     --data-only --no-owner \
     -t canonical_works -t work_editions -t aozora_manifest_entries \
     -t canonical_work_review_queue -t sources -t source_chunks \
     -t thought_cards -t thought_evidence_links -t thought_questions \
     -t judgment_rules -t judgment_rule_versions -t judgment_rule_evidence \
     -t creative_profiles -t creative_cards > backups/phase_c_data.sql
   # 復元
   docker exec -i supabase_db_thinker-soseki psql -U postgres -d postgres -q \
     -v ON_ERROR_STOP=1 --single-transaction \
     -c "set session_replication_role = replica;" -f - < backups/phase_c_data.sql
   ```
   最新の退避が `backups/phase_c_data.sql`（199MB・gitignore 済み）にある。
   これを失った場合の完全再構築は §12.1 の CLI 手順 + Phase C の ingest +
   `retag`（LLM 数ドル・数時間）。
2. **PostgREST は1リクエスト最大1000行**。全件取得は必ず
   `worker/src/aozora/paged.py` を使う。3回踏んだ（retag / snapshot / cli report）。
3. **思想カードを承認したら `gen-questions` を必ず流す**。代表質問が無いと
   Thought Router が当てられず全部フォールバックへ流れる（気づきにくい劣化）。
4. **人物辞書（characters.json）を変えたら** `retag --source <source_id> --force`
   でその作品だけ付け直す。worker と frontend の辞書は複製で、同期テストが落ちる
   ので片方だけの変更はコミットできない。
5. CLI へ複数IDを渡すときは1件ずつループする（zsh の変数展開は単語分割されない）。
6. snapshot 基準は `worker/snapshots/phase_c.json`。**LLM由来のタグは指紋に
   含めない**設計（含めると再現性検証が壊れる）。
